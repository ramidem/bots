# Research: extensive site audit format

Date: 2026-11-09. Seed: the owner’s Safari Google search for a good extensive site audit format. SERP HTML blocked; research extended via direct pages listed in `sources.md`.

## Verdict

A good extensive format is **not** a 200-row dump. It is:

1. **Fixed report shell** — metadata, six area scores, findings table, measurements, not-measured, evidence paths.
2. **Fixed business checklist** — the owner’s Offers Tracker **14 checks** (conversion-first for freelance lead audits).
3. **Layered technical probes** — crawl → on-page → speed → a11y → schema → security/mobile, used to **justify area scores** and extra findings (check_number null when outside the 14).
4. **Severity triage** — P0 / P1 / P2 with evidence; unknowns default ≤ P2 (never invent P0).
5. **Machine twin** — `audit.md` for humans, `audit.json` matching `audit-schema.ts` for Sales / <app-repo>.

That matches industry practice (CheckRun compactness + CrawlRaven dependency order + LegalClarity field discipline) and the owner’s stop line (findings + suggested offer IDs only).

## What the search results agree on

| Theme | Consensus |
|---|---|
| Start order | Crawl/index blockers first; speed and schema after the page is reachable |
| Core Web Vitals | Cite real runs: LCP ≤ 2.5s, INP ≤ 200ms, CLS ≤ 0.1; prefer field when available, always label lab vs field |
| Evidence | Every fail needs a URL and/or saved artifact (HTML, Lighthouse JSON, screenshot path) |
| Structure | Sections or categories with Pass / Fail / N/A / Unknown |
| Prioritization | Blocking > diluting > refining (map to P0 / P1 / P2) |
| Scope | Sample by template (home, service, contact, blog) unless the site is tiny |
| Schema | JSON-LD preferred; validate with Rich Results Test / schema.org validator |
| A11y | WCAG 2.2 AA signals: alt, contrast, labels, keyboard, focus |
| Security (light) | HTTPS, mixed content, basic headers, cert expiry — not a full pen test |
| 2026 extras | AI crawler access / `llms.txt` optional notes; do not invent AI-visibility scores |

## What to reject for the owner’s audits

| Pattern | Why |
|---|---|
| Overall “site score” out of 100 | Spec 009: six area scores only, no overall |
| Pitch / pricing / redesign quote in the report | Sales owns offers; Site Audit stops at findings + offer IDs |
| Estimated speed numbers | Schema forbids measurements without `tool` + `run_at` |
| Overwriting prior audits | Re-audit = new dated folder/file |
| Contacting the lead or submitting forms | Needs explicit ask |
| 197-check client-facing dump | Use as probe bank; report only findings that matter |

## Mapping industry layers → the owner areas

| Industry layer | the owner `area` | Feeds checks / scores |
|---|---|---|
| Crawlability, robots, sitemap, canonicals, titles, meta, H1, internal links | `seo` | Area score + optional extra findings |
| Thin/duplicate content, freshness, E-E-A-T signals, proof for buyers | `content` | Checks 9–11, 13 + area score |
| LCP / INP / CLS, weight, mobile | `speed` | Check 14 + area score |
| Alt, contrast, labels, keyboard | `accessibility` | Area score + optional findings |
| Booking, forms, CTAs, portals, third-party intake | `conversion` | Checks 1–8, 12 |
| JSON-LD / OG / rich-result types | `schema` | Area score |

## Offers Tracker 14 checks (canonical labels)

From the <example-lead> production audit (Offers Tracker > Audit checklist, read 2026-10-28):

1. Online booking  
2. Inquiry / lead form  
3. Response promise  
4. Phone-only contact  
5. Ordering path  
6. Order / job status  
7. Client portal  
8. Third-party stopgaps  
9. Multiple branches  
10. Hiring process  
11. Content freshness  
12. Past-customer follow-up  
13. B2B call path  
14. Speed and mobile  

If the live sheet differs later, the sheet wins; update this list and the template in the same change.

## Recommended deliverable shape

```
audits/<lead>/
  audit.md          # human report from TEMPLATE.md
  audit.json        # machine twin (audit-schema.ts)
  lighthouse-*.json # optional evidence
  html/…            # optional saved HTML / notes
```

Shared Sales copy: `<shared>/Data/audits/<lead>.md` (short summary only).
